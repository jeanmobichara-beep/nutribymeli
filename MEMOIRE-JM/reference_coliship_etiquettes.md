- **Rognage** : `/Users/pommezmelissa/.local/bin/rogner-colissimo [pdf…]` (créé le 05/10/2026). Transforme les PDF ColiShip A4 paysage en étiquettes seules 100 × 150 mm, échelle 1:1, fusionnées dans `~/Downloads/Etiquettes rognées <date>.pdf`. Sans argument : tous les `Colissimo_*.pdf` des Téléchargements. JM passait avant par un site en ligne pour rogner.
- **Import en masse** : kit officiel (guide + .FMT + exemples) = `https://www.colissimo.entreprise.laposte.fr/media/386/download?attachment` (un zip malgré le nom). Format utilisé : « 01-fr-fr sans code produit », 17 colonnes séparées par `;`, CRLF, poids en grammes, 35 caractères max par ligne d'adresse, Adresse1 = n° et voie, Adresse4 = lieu-dit. Le .FMT se charge dans Paramètres > Import, le fichier dans « Automatiser l'affranchissement ».
- **Poids colis VitalDésir (donnés par JM le 05/10/2026)** : 1 sachet = 150 g, 2 sachets (DUO) = 300 g, 3 sachets = 430 g. Ne pas reprendre le poids Shopify (120 g ou 0 g).
- **Module ColiShip Mac** : signé La Poste mais non notarisé, d'où le blocage Gatekeeper ; installé dans `/Applications` le 05/10/2026 après vérification de la signature. Sert à l'impression directe, pas à la création en masse.
- Les commandes Guadeloupe / Martinique ne passent pas par l'appli Shopify de JM : elles se font sur ColiShip, expéditeur à Petit-Bourg. Voir [[feedback-shopify-cles-api-pas-mcp]].
- **Règles d'import constatées le 05/10/2026 (8 colis Antilles)** : code pays = `FR` pour la Guadeloupe et la Martinique (`GP` / `MQ` = erreur « code pays ou code postal incorrect ») ; la commune doit être le libellé La Poste du code postal, avec abréviations (`STE ROSE`, `ST ESPRIT`, `ST JOSEPH`, jamais « SAINTE ROSE » ni « SAINT-JOSEPH »). Le triangle rouge n'affiche rien : l'erreur se lit en ouvrant le colis avec le crayon. Corrigé à la main par JM = taper le code postal et cliquer sur la commune suggérée.
- **Commande unique `expedier-shilamaya` (05/10/2026)** : `/Users/pommezmelissa/.local/bin/expedier-shilamaya` = contrôle seul (commandes Shopify non traitées GP/MQ validées par `checkGenerateLabel`, rien d'affranchi) ; `--envoyer` = étiquettes réelles par l'API Colissimo (PDF 10 × 15, sans rognage) puis traitement Shopify avec suivi et notification client. 🔴 `--envoyer` engage un affranchissement et un mail client : jamais sans l'accord de JM sur la liste du contrôle. Au 05/10, seul le contrôle est testé (8 colis OK) ; `--envoyer` n'a jamais tourné (lecture de la réponse `generateLabel` et mutation `fulfillmentCreate` non éprouvées). Clé : `COLISSIMO_API_KEY` dans `dashboard/.env.local` (Colissimo Box > Mon compte > Gestion des utilisateurs > crayon ; ne jamais la régénérer, l'appli Colissimo de Shopify s'en sert sans doute). Produit `COLD` accepté pour GP → GP/MQ ; `DOM`, `COM`, `CDS` refusés. L'API ne contrôle PAS la cohérence commune / code postal (une ville fausse passe) : relire la liste. Métropole et autres destinations ignorées (douane CN23 non gérée).
